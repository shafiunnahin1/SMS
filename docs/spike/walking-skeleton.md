# Walking Skeleton Spike (Revision 7)

## কেন
এই প্ল্যান ১৪৩ টেবিল, ~৩৮ মডিউল, ৪ ধরনের প্রতিষ্ঠান নিয়ে — কিন্তু **একটি লাইনও চালানো হয়নি**। প্ল্যানের সময় ও ঝুঁকির কোনো অনুমান নেই (মূল প্ল্যানে ছিল, আমার পুনর্লিখনে মুছে গেছে)। Spike-এর কাজ তিনটি: (১) প্ল্যান *বাস্তবে নির্মাণযোগ্য* কি না যাচাই, (২) যে ভুল/অস্পষ্টতা আছে তা প্রথম সপ্তাহেই ধরা, (৩) **প্রকৃত গতি মাপা**, যার উপর ভিত্তি করে বাকি কাজের সময়-অনুমান হবে। কোনো সময়-সংখ্যা আমি এখানে বসাইনি — বসালে তা প্রমাণ ছাড়া নির্ভুল দেখাত।

## পরিধি — "এক টুকরো, পুরোটা, তিন ধরনে"
Phase 0–2 (scaffold, schema, tenancy, auth, bootstrap, enrollment) + **একটি vertical slice**:

> **ছাত্র ভর্তি → batch-এ enrollment → বকেয়া দেখা → ফি আদায় (cash, একাধিক লাইন) → রসিদ PDF → অভিভাবক নিজের সন্তানের বকেয়া ও রসিদ দেখে**

— `school`, `coaching`, `private_batch` এই **তিন demo tenant-এ**, তিন host-এ (`*.lvh.me`), তিনটি আলাদা থিম/layout-এ।

### ইচ্ছাকৃতভাবে **বাদ** (spike-এ নয়)
অনলাইন পেমেন্ট, SMS (শুধু log driver), কাস্টম ডোমেইন, পাবলিক সাইট, Super Admin panel-এর বেশিরভাগ, theme editor, সব Phase 7 মডিউল, PDF-এর সাজসজ্জা। Spike মানে "সবকিছুর পাতলা অংশ" নয়, "একটি পথের পুরোটা, কিন্তু সত্যিকারের"।

### Spike-কালীন নির্দিষ্ট প্রশ্ন (উত্তর লিখতে হবে)
1. `schema.sql` থেকে সরাসরি Laravel migration লেখা কতটা সহজ? কোন constraint (UNIQUE with NULL, ENUM, JSON, generated column) সমস্যা করল?
2. Fail-closed scope: প্রথম দিনে কয়টি "ভুলে tenant বাঁধা নেই" exception এল, এবং সেগুলো কি *বৈধ* ছিল (কোড-ত্রুটি), না নকশা-ত্রুটি (এমন জায়গা যেখানে tenant সত্যিই থাকা সম্ভব নয়)?
3. `EnrollmentService` + cache (`students.program_id/batch_id`): কোথাও সরাসরি লেখার প্রলোভন/প্রয়োজন এল কি?
4. `FeeService::dueLines()` ১০০০ ছাত্রে কত ms? (N+1 আছে কি?) — একবার মাপুন, লক্ষ্য ঠিক করার জন্য নয়, ঝুঁকি দেখার জন্য।
5. তিন tenant-এ ThemeProvider: প্রথম লোডে রঙ ঝলকায় কি? CSS variable + `color-mix` সব ব্রাউজারে (Android Chrome, পুরনো WebView) কাজ করে কি?
6. Sanctum `authenticateAccessTokensUsing`-এ idle-timeout প্রত্যাশামতো কাজ করছে কি? (installed version-এ যাচাই — plan-এর কোড সংস্করণ-নির্ভর)
7. Bearer vs cookie-SPA (S7): কোনটি কম জটিল, কোনটি নিরাপদ, মোবাইল অ্যাপ (Phase 10) কী চাইবে?
8. UI Pack: hook/view বিভাজন কি সহজে হলো, নাকি প্রতিটি পাতায় ঠেলে করতে হলো? একটি বিকল্প view বানাতে কত লাগল, এবং `PackContractTest` কী কী ধরল? (এটিই পর্যায় C-র সময়/খরচ-অনুমানের ভিত্তি)
9. ভাষা: PDF-এ বাংলা যুক্তাক্ষর ও আরবি শেপিং কোন engine-এ ঠিক এল? `Intl`-এর `bn-BD` ও Latin-অঙ্ক-ফ্ল্যাগ পুরনো Android-এ চলল? gateway-র Unicode SMS ফ্ল্যাগ কী? আরবির ১৭px/১.৮ প্রস্তাব কেমন লাগল?
10. একজন নতুন ডেভেলপার/এজেন্ট শুধু `AGENTS.md` + `docs/BUILD-SEQUENCE.md` পড়ে কতদূর গেল, কোথায় আটকাল?

## Gate — Spike শেষে সিদ্ধান্ত
| ফল | মানদণ্ড (প্রস্তাব) | পরবর্তী কাজ |
|---|---|---|
| **Go** | slice তিন tenant-এ পুরো চলে; `TenantFailClosedTest`/`TenantModeTest` সবুজ; rework ≤ ২০% (এই সীমা আমার ধারণা — আপনি ঠিক করুন); কোনো মৌলিক নকশা-ত্রুটি নেই | সময়-অনুমান spike-এর গতি থেকে; Phase 3–4 শুরু |
| **Adjust** | slice চলে কিন্তু ৩+ spec-ভুল/অস্পষ্টতা ক্লাস পাওয়া গেছে (একই ধরনের) | প্ল্যান সংশোধন (Revision 8) **আগে**, তারপর Phase 3 |
| **Stop/Rethink** | tenancy/fail-closed বা enrollment/fee নকশা মৌলিকভাবে অচল; rework > ৫০% | নকশা-পুনর্বিবেচনা, দায়িত্বপ্রাপ্ত ব্যক্তির সাথে বৈঠক |
Gate-এর ফল ও কারণ `docs/SPIKE-LOG.md`-এর শেষে লেখা; **মালিকের স্বাক্ষর ছাড়া Phase 3 শুরু নয়**।

## Spike থেকে যে সংখ্যাগুলো বের হবে (কিন্তু এখনো নেই)
- **গতি:** কর্ম-ঘণ্টা ÷ (slice-এ থাকা endpoint + page + টেবিল-সংখ্যা) = একক-ইউনিট খরচ। এটিকে Phase 4–7-এর ইউনিট-সংখ্যা (প্ল্যান থেকে গোনা) দিয়ে গুণ করে প্রাথমিক পরিসর (সর্বনিম্ন–সর্বোচ্চ, একক সংখ্যা নয়)।
- **ঝুঁকি-ফ্যাক্টর:** প্ল্যান-ত্রুটির হার (প্রতি ধাপে) থেকে অনুমান করা পরবর্তী ধাপগুলোর ত্রুটি-হার; বাকি কাজে কতটা buffer।
- **Release 1 কাটা-ছাঁটা:** অনুমানের সাথে `docs/reports/QUALITY-ANALYSIS.md` §৫.২-এর প্রস্তাব মিলিয়ে মালিক সিদ্ধান্ত।

## এজেন্টের নির্দেশ (Spike-এর সময়)
- নিয়ম আগের মতোই (`AGENTS.md`); অতিরিক্ত: **প্রতিটি ধাপ শেষে থামুন, `SPIKE-LOG.md` পূরণ করুন, তারপর এগোন।**
- spec-এর কোড কপি করার আগে পড়ে দেখুন; ভুল পেলে *ঠিক করে এগোবেন না* — প্রথমে লগে লিখুন (ভুল কোথায়, ঠিকটি কী, কোন spec ফাইল), তারপর সংশোধন। লক্ষ্য — spec উন্নত হওয়া, শুধু কোড চলা নয়।
- কোনো কিছু আন্দাজে সম্পূর্ণ করবেন না; "পরে দেখব" নয়। অস্পষ্ট হলে `DECISIONS.md`-এ প্রশ্ন + আপনার বেছে-নেওয়া উত্তর + কেন।
- সময় বাঁচাতে test বাদ দেবেন না — test-ব্যর্থতার কারণ-বিভাজনই আমাদের সবচেয়ে মূল্যবান ডেটা।
