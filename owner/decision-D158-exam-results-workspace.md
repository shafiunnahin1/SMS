## প্রস্তাবিত সারি
| D158 | R2.1.7 scope: exam menu group, folder-style results workspace, exam-to-question-paper link, per-question-type mark entry, MCQ import by JSON and OMR | Owner approved (2026-10-24). R2.1.7 may be built, after R2.1.6, with this refined scope only. Existing tables, grade/pass/publish rules and permissions are reused: `exams`, `exam_subjects` (`components`), `results` (`component_marks`), `ResultService`, publish and merit list. (1) Menu: the admin menu gets one group "পরীক্ষা" (like the fee group). It holds every question-bank item and every exam/result item (exams, result entry, admit cards, merit list, result sheets); teachers get the same group with their own items. No route changes. (2) Results workspace: folders by year (`exams.academic_year`), then class/batch (program, batch), then each exam as a file. Opening an exam shows result entry, publish, merit list and "link a question paper". (3) Link: new tenant table `exam_papers` (institution, exam_subject_id, qb_paper_id, linked_by, timestamps; unique per exam subject). Only a FINAL paper of the institution can be linked. One paper may be linked to many exams. The picker is a file-open dialog that starts at the question-paper home and its folders (D126); it cannot pick from another institution, and unlinking is allowed until results are published. (4) Mark fields: one input per question kind on the linked paper - MCQ, creative (CQ), short answer (সংক্ষিপ্ত); MCQ only = 1 field, MCQ+CQ = 2, CQ+MCQ+short = 3. Linking sets the exam subject's `components` from the paper (full marks = the paper's marks per kind; pass marks editable as today). Without a link, entry stays as today. The list shows every enrolled student of the class/batch (roll, name) with the fields beside each name. Written parts are entered by hand. (5) MCQ by JSON: the page shows a copyable AI prompt with the student list (roll, name), the exam/subject, the MCQ full marks and a JSON example, e.g. `{"exam_subject_id":12,"results":[{"roll":"101","mcq":18.5}]}`. Pasted JSON is checked (unknown or duplicate roll, marks above full or below 0, wrong exam) and shown as a preview; only valid rows are saved, into the MCQ component only. (6) MCQ by OMR: from the linked paper's OMR form (D127), only reviewed scans whose roll matches an enrolled student are taken. Their obtained marks go into the MCQ component after a preview; uncertain or unreviewed sheets are never counted, and a re-import updates instead of adding twice. (7) Published results stay locked (existing rule). Every import and link is written to the audit log. Tests: tenant isolation (404), the field count per paper kind, the JSON validation cases, OMR import without doubling, published lock. Implementation commits carry `Change-Request: D158`; the guard map gains `R2.1.7 -> D158` and the table `exam_papers`. |
