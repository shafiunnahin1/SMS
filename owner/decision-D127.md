# D127 — draft for the owner (copy the row below into docs/LOCKED-DECISIONS.md right after the D126 row)

| D127 | R2.1.6 scope: OMR answer sheets for final papers - make, print, scan in the browser, review, grade | Owner approved (2026-10-19). R2.1.6 may be built, after R2.1.5, with this refined scope; screens keep qbank's look and order (D110: form settings, sheet preview, scan, batch review, results). For the head teacher/admin and teachers of the institution (a teacher: their own papers' forms). (1) Form: one OMR form per FINAL paper (QB.8/D126), for its MCQ questions; settings as qbank - title, roll digits 1-12, options 2-5 labelled ক-ঙ or A-E, info boxes (class, roll, subject, set), page size/orientation, answer columns, marks per question, negative marking on/off and amount, multiple-mark policy (wrong / correct if any matches); the layout is editable until "generate", then locked (unlock = a new layout version; scans keep the version they were read with). New tenant tables `qb_omr_forms` (paper, code, settings JSON, layout version, locked_at) and `qb_omr_scans` (form, layout version, set code, roll, matched student, answers JSON, answered/correct/obtained marks, status, comparison JSON, image path on the private disk, source upload/camera, reviewed_by); schema.sql updated in the implementation commits. (2) Print: the sheet is drawn by SMS's own Chromium PDF (D50) with qbank's corner markers, header code and bubble geometry (one geometry shared by print and scan), one sheet per set code; no html2canvas/jsPDF. (3) Scan: in the browser, as qbank - an uploaded photo/image or the device camera (qbank's camera auto-capture); qbank's own canvas reader (marker search, homography, bubble fill thresholds, roll/set/answer decoding) is ported into SMS's frontend code unchanged in its rules, no OpenCV and no outside service; a PDF of scanned sheets is read with a local copy of pdf.js 3.11.174 (Apache-2.0) and HEIC photos with a local heic2any 0.4.5 (MIT) - both copied unchanged into `frontend/public/vendor/` with a MANIFEST.sha256 as D119/D122 (the guard rule extended to them in its own guard commit); the image never goes to another server, only the read result and the sheet image to SMS. (4) Review: every sheet is checked before it counts - an unreadable roll/set digit (`?`), a multiple mark, a blank, an unknown set code (use the main set or cancel the sheet), the same roll twice on one form (update or keep both - never silent) and a roll that matches no student are shown for a person to fix; batch review of up to 200 sheets with per-sheet save results (saved/failed/skipped); a person may correct any answer; nothing uncertain is counted automatically. (5) Grading: qbank's - correct x marks - wrong x negative (when on); multiple-mark policy as set; the key is the frozen set's own (D126 (2)), so a later question edit never changes a grade; results list and CSV download per form; matching a roll to a student uses the paper's program/batch enrollment roll. Putting OMR marks into an exam's results is R2.1.7, not here. (6) Limits in config: 10 MB per image, 200 sheets per batch. Acceptance: golden sheets (each set, every answer kind) read exactly; rotated/skewed, blank, double-marked, unreadable-digit, unknown-set and duplicate-roll sheets reach review, never a silent score; a re-scan never doubles; other institution 404. Implementation commits carry `Change-Request: D127`; the guard map gains `R2.1.6 -> D127` and the two tables in a separate guard commit merged to main first. |
