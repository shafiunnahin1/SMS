# Draft Decision D180: edit finalized question-paper settings through immutable revisions

> Owner review draft only. It does not change `LOCKED-DECISIONS.md`, the guard, or application code. To approve this exact scope, run `owner\approve-D180.ps1` after reviewing this file. The script creates two local commits and does not push.

## 1. Owner request (2026-10-28)

The settings block marked in the final-paper screen must never be disabled. The editable fields are title, exam name, duration, set count, instructions, group-by-subject, and subject order. The questions, sections, marks, and question wording are not part of this block.

## 2. Proposed contract

1. A finalized paper's settings block remains editable. Saving a changed setting creates the next immutable revision of the same logical paper; a no-op save creates no revision. The active revision remains final after the save. Question/section content and per-question marks remain frozen and cannot be changed through this settings form.
2. Each revision snapshots the red-block fields and owns its frozen set layouts and answer keys. A later revision never updates or deletes an earlier revision, its variants, or its print output. The paper list and existing paper URL open the latest revision by default; a revision selector/history view and the print endpoint can open an older revision explicitly.
3. Set count follows D173 (1-255). A changed count creates variants only in the new revision. Subject grouping and the chosen subject order are applied only to the new revision's variants (D128); prior revisions keep their printed grouping and order. The existing deterministic set strategy and D173 set-code rules apply independently to each revision.
4. Add tenant table `qb_paper_revisions` with paper id, positive revision number, immutable snapshot JSON for the settings block, actor, and timestamps; unique `(institution_id, qb_paper_id, revision_number)`. Backfill every existing paper as revision 1 without changing its current variants or OMR data. Add a revision FK to `qb_paper_variants`, backfill existing variants to revision 1, and make the variant-number uniqueness revision-scoped. The latest revision number identifies the current settings; no mutable history row or delete path is added.
5. Amend D127's one-OMR-form-per-final-paper rule to one form per paper revision. Add a revision FK to `qb_omr_forms` and make its paper uniqueness revision-scoped. Existing forms become revision 1; scans remain attached to their original form and `layout_version`. A new revision has no generated OMR form until requested; when creating one, default its settings from the previous revision's form without changing that old form or its scans. Editing settings is never blocked by prior scans.
6. Existing API endpoints continue to address the logical paper. `PUT /question-bank/papers/{id}` on a final paper accepts only the red-block settings, creates a new revision and its frozen variants atomically, and rejects section/item/marks changes. `GET /question-bank/papers/{id}/revisions` lists the caller-visible revisions; print/preview and OMR creation accept an optional revision number and default to the latest. Preserve current tenant/role/teacher ownership rules, audit each new revision with changed setting keys only, and keep old revisions readable.
7. Scope is R2.1 screen/API/schema work under task QBO.2, after QBO.1. It may add the one table above and additive migrations/columns only for `qb_papers`' existing variants/forms workflow. No package. Implementation commits carry `Task: QBO.2` and `Change-Request: D180`.

## 3. Acceptance examples

- On a final paper, changing any red-block field keeps the old revision byte-for-byte unchanged and creates one new final revision; repeating the same values creates no extra revision.
- Changing set count, grouping, or subject order changes only the new revision's variants and answer keys; the old revision prints exactly as before.
- An existing OMR scan still resolves the old form and layout version after a later paper revision. The new revision can create its own form and scans.
- A teacher can revise only their own paper; the institution admin can revise institution papers; a foreign-tenant paper remains unavailable.
- Question, section, item, marks, and answer content cannot be altered by the final-settings update.
