## Why this scope is needed

D96 permits technical refinement, but D98 explicitly limits strict design-only inventory to two named tables. A separate receipt is a third table, so the owner must narrowly extend that limit before schema or tooling changes. The existing committed event unique key cannot represent one incoming request across several slot events, and per-slot key derivation alone cannot enforce root payload identity or record zero-slot success. AuditLog is platform-held and omitted from tenant export; it is not an accepted replay store.

The selected structure keeps operation identity separate from slot state and history. Receipt linkage and minimal result references must be validated together with future export/import ID mapping; an opaque JSON result is not automatically safe to copy into another tenant. Do not assume existing export tooling can remap such a manifest. Design checks must reject unsafe manifests or define explicit remapping before implementation acceptance. Receipt retention must define the replay guarantee and prevent silent key reuse within that guarantee; no arbitrary retention period is selected here.
