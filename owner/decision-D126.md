# D126 — draft for the owner (copy the row below into docs/LOCKED-DECISIONS.md right after the D125 row)

| D126 | R2.1.5 scope: question-paper folders, many sets (variants), blueprints and print, on SMS's existing papers | Owner approved (2026-10-19). R2.1.5 may be built, after R2.1.4, with this refined scope; screens keep qbank's look and order (D110). qbank's "question set" IS SMS's existing `qb_papers` (QB.8: sections, per-question marks, duration, total, instructions, draft/final, Chromium print, purchase confirmation) - no second question-set entity. For the institution's head teacher/admin and teachers, as QB.8 (a teacher's own papers, the head teacher sees all), inside their institution only. (1) Folders (qbank's): a new tenant table `qb_paper_folders` (institution_id, parent_id, name, created_by) and `qb_papers.qb_paper_folder_id`; folders nest; a move into itself or its own sub-folder is refused; a folder is deleted only when empty; moving papers between folders. (2) Sets/variants (qbank's subsets): replaces the fixed A/B with qbank's rules - strategy "options" (MCQ options shuffled), "serial" (questions shuffled inside each section) or "both"; 1-26 sets named A-Z or ক-ঞ (qbank's other name lists are not needed); qbank's capacity check (no more sets than distinct orders allow); deterministic seeds (the same set is always printed the same); when a paper is made final every set is frozen in a new tenant table `qb_paper_variants` (paper, number, code, strategy, layout_json = question order + option order + correct labels per question), so a later edit of a question never changes a printed set; each set has its own answer key. (3) Blueprints (qbank's assessment blueprints): platform tables `qb_blueprints` (name bn/en, class level, subject, exam type, total marks, duration, active) and `qb_blueprint_items` (section title, question type, count, marks each, optional chapter/topic/difficulty), written by the Super Admin; a teacher builds a paper from a blueprint: eligible questions (published; free or already bought by the institution; matching type/subject/chapter/topic/difficulty) are picked in qbank's deterministic order; a slot without enough eligible questions is shown as short - never filled from outside the rule; a picked question can be swapped for another eligible one; paid questions still need the QB.8 purchase confirmation before final. (4) Print (existing Chromium engine, D50): the set code in the header ("সেট খ"), optional 2 columns as qbank, Bangla/English, LaTeX, pictures, graphs/diagrams (D118), and a separate answer-key print per set. (5) New tables/columns above are added to schema.sql in the implementation commits; tenant tables use BelongsToInstitution (D25). (6) Acceptance: folder move/cycle/empty-delete, sets deterministic and frozen at final, capacity limit, blueprint picks and "short" slots, eligibility (unpublished/unbought not picked), answer key per set, other institution 404. Implementation commits carry `Change-Request: D126`; the guard map gains `R2.1.5 -> D126` and the new tables in a separate guard commit merged to main first. OMR stays in R2.1.6. |
